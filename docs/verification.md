# 검증 기록

모델: 공식 PDK 260820(`05cmos_mosfet_corner.lib` TT/SS/FF/SF/FS, nmos4/pmos4), ngspice-42.
Vt 불일치는 PDK에 모델이 없어 Pelgrom 계수 A_VT = 12(N) / 15(P) mV·µm를 가정했다.
각 단계 끝의 **판단**은 그 단계까지 본 것으로 이 주제가 칩으로 동작할지에 대한 결론이다.

| Vt 기울기 (Q = 0 쪽) | DC 보존 전압 | 데이터를 잃는 V_hold | 잃기까지 걸린 시간 |

- DC 보존 전압보다 높으면 100 s 동안 그대로다. 낮으면 1–2 s 안에 Q와 QB가 뒤바뀐다
- 처음 수백 ms 동안은 저장된 1이 새 VDDA보다 높은 채 남아 누설로만 천천히 내려간다. 그래서 짧은 유지(µs–ms)로는 보존 전압보다 훨씬 낮은 VDDA에서도 데이터가 남아 보인다
- 0.30 V 이하에서는 두 노드가 거의 같은 전압(차이 약 10 mV)으로 모이고, 5 V로 올릴 때 셀이 원래 기우는 값으로 정해진다. 기울기 0인 셀은 이때 1로 돌아왔다. 한 패턴만 보면 실패를 놓친다

**판단**: 5 V 동작은 모든 코너에서 여유가 크다(쓰기 트립 1.66 V 이상, SNM 1.26 V 이상). 물리 결함 실험의 두 손잡이가 모두 측정 가능한 범위에 있다. 보존 실패는 VDDA 0.34–0.42 V 근처에서 셀마다 퍼져 나오고(10 s 이상 유지 필요), 읽기 실패는 VDDA 약 1.4 V에서 나온다. 측정 계획은 [spec.md](spec.md)의 측정 계획 3에 반영했다.

## 7. ETRI 문의 대신 선례로 정한 것 (2026-11-03)

문의할 거리였던 두 가지를 제작된 선례 칩과 공식 문서로 정했다. 결론은 둘 다 문의 없이 진행이다.

| 질문 | 근거 | 정한 것 |
|---|---|---|
| PANA를 셀 어레이 전원(VDDA)으로 써도 되나 | GPIO 문서(02_ETRI_5V_GPIO_260615) 비고 4: 저항 포트(PADR)는 그대로 쓸 수 있고, 저항 없는 포트(PAD)만 사전 협의 또는 설계자 ESD 고려가 필요하다. 선례 pong_pt1(MPW2025 STD-II, 제작됨)은 PANA 6개를 모두 PADR로 썼다(표준셀 시험 핀) | VDDA, VDDW 모두 PANA의 **PADR**로 받는다. 이 핀의 전류는 누설과 쓰기 전하(평균 수 µA)뿐이라 약 0.7 kΩ에서 생기는 강하는 mV 수준이고, 쓰기 순간 전하는 칩 안 디커플링(57 pF, 28.5 pF)이 댄다. 디커플링 게이트도 PADR 뒤라 ESD에서 보호된다. VDDA·VDDW ≤ VDD로 쓰고 VDD를 먼저 켠다 |
| PVDD 1개·PVSS 1개로 충분한가 | GPIO 문서에 전원 패드 개수 규정은 없다. 선례 FIR_PE(2024-3차 MPW240925002, 제작됨)는 PVDD 2·PVSS 1, pong_pt1은 PVDD 3·PVSS 4 | 선례 범위로 맞췄다: **PVDD 2, PVSS 3**. 핀을 내려고 DOUT_RAW 4핀을 없애고 원시 보기를 읽기 모드 11 + FI_POS0으로 옮겼다(8절). 남는 핀 하나는 비트라인 드라이버 전원 VDDW로 따로 뺐다(9절) |

함께 선례대로 정한 것: 출력 패드는 두 선례가 쓴 POB8, GPIO 셀은 ETRI 라이브러리 원본(ETRI_NSPL_GPIO_250610) 그대로, 실링·CHIPBOUNDARY는 넣지 않음(관리자 답 #1226, 두 선례 GDS), 오픈소스 DRC·LVS 결과로 접수(관리자 답 #1273, FIR_PE 접수서). 처음 검토의 "한 학생이 설계 두 개" 질문은 SRAM만 내기로 해서 필요 없어졌다.

- 핀 쪽: 왼쪽 W 패드 입력 7, 아래 S 패드 입력 5 + PRE_N·WD·SENSE 17, 위 N 패드 입력 3 + 출력 6, 오른쪽 워드라인 30
- 합성 347셀(0.177 mm²), qflow 489.6 × 481.05 µm, 평면 LVS 일치(2,242 소자), 금속 틈 메우기·격자 뒤 공식 DRC 0, `extra_checks.sh` 0, 매크로 핀 70개
- 고친 것: GrayWolf가 DISPLAY가 있으면 그림 창을 열려다 X 서버가 없어 멈췄다(`run_flow.sh`에서 DISPLAY를 지움). 종횡비 1.0에서 VIA2가 VIA1 위에 한 곳 쌓였다(11.VIA2.S_Stack) → 기본 종횡비 1.02(같은 크기, 쌓임 없음)

## 9. 비트라인 드라이버 전원 VDDW와 디커플링

- 매크로에서 비트라인 드라이버의 N-well·소스를 VDDA에서 떼어 VDDW 버스(오른쪽 x 60–72λ)로 냈다. 매크로 Magic DRC 0, KLayout DRC 0, LVS 일치, 추가 규칙 0
- 쓰기 Vmin(VDDW, VDDA = 5 V에서 저장 1에 0 쓰기, `sweep_vdda.py`): 1.73 V(FF 125 °C) – 1.94 V(SS 0 °C), TT 27 °C 1.86 V. 셋째 물리 결함 손잡이다

## 12. 방향을 아는 복호 (2026-11-08, 브랜치 direction-ecc)

브랜치 reliability-monitor(카나리 래치·RO 뱅크, 동작이 트랜지스터 모델에 기대는 회로)는 그대로 두고, main(744acdd)에서 새로 갈라 코어 위쪽 빈 곳에 디지털 블록 하나만 넣었다. 제어 블록에서 복호를 떼어 복호 블록 `ecc_dec`(조합 논리)로 옮기고, 읽기 모드 11의 FI_POS[2:1] = 01을 방향 보기로 썼다(사양은 [spec.md](spec.md)). 핀 28개, 쓰기 모드 00–11, 읽기 모드 00–10, 원시 보기(FI_POS 000·001·1xx), 주소 15, 타이밍 규칙은 그대로다.

근거: 8T 셀의 저전압 읽기 실패(VDDA)와 쓰기 실패(VDDW)는 0 → 1 한 방향이다(2·9절). 확장 해밍 (8,4)는 자기 쌍대라 한 방향 3비트 오류의 신드롬 자리는 늘 0으로 읽힌 비트이고, 방향을 아는 복호는 표준 복호가 오정정하는 그 112가지를 모두 검출한다. 16개 부호어의 한 방향 오류를 모두 대 본 결과는 spec.md의 표와 같다(1비트 64 고침, 2비트 28 고침·84 검출, 3비트 112 검출, 4비트 56 검출·28 오정정).

설계 흐름과 별개로 코드·넷리스트·GDS를 일회성 스크립트로 다시 확인했다. 막는 결함은 없었다. 확인한 것: main과 브랜치의 제어 쪽 출력(WD, WWL, RWL, PRE_N)과 복호 출력이 방향 보기를 빼고 같다는 형식 등가(yosys SAT, 쓰기 주기와 CLK = 0 포함, 등가 조건을 빼면 실패하는 음성 대조), ecc_dec와 두 독립 모델의 2,048가지 일치, 고정 넷리스트(.v, .spc)와 RTL의 등가, 금속만으로 뽑은 연결(11개 연결 넷과 출력 6개의 패드 대응, 복호 블록 전원), VIA2가 VIA1 위나 0.6 µm 안에 없음, `chip_sim.py` 모델과 기대값. 고친 것: 방향 보기 읽기는 DIN = 0이어야 한다는 절차(사양·안내·pins.csv), DIN 반전으로 만들 수 있는 3비트 패턴은 쌍 {2m, 2m+1}을 품은 24가지뿐이라는 것, 프리차지 구간 확인을 시험에 되살림, 기판·우물 접점 검사를 `check_all.sh`에 넣음, 낡은 주석.

### 칩 코어 트랜지스터 모의

`sim/chip/chip_sim.py`: 코어 전체를 소자 + 기생 C × 1.5로 추출(소자 4,236, 기생 C 12,041). 10절의 21주기 뒤에 16주기를 더한 37주기(200 ns), 읽기 25번을 ECC 모델과 비교한다. 더한 읽기는 방향 보기 8번(데이터 0의 2비트 저장 오류, 3비트 저장 오류, 데이터 F의 1 → 0 2비트 오류를 두 방향으로, DIN 반전으로 만든 1비트 오류 3번(두 방향), 기준 워드의 1비트 저장 오류), 같은 워드의 정상 읽기 3번, FI_POS[2] = 1인 원시 보기 1번이다. 출력은 CLK 하강 5 ns 전에 읽는다.

| 조건 | 읽기 25번 |
|---|---|
| TT 27 °C, 5 V | 모두 맞음 |
| SS 125 °C, 4.5 V | 모두 맞음 |
| FF 0 °C, 5.5 V | 모두 맞음 |
| TT 27 °C, VDD 5 V, VDDA = VDDW = 2.0 V | 모두 맞음 |

25번 모두 DOUT·SEC·DED가 모델과 같고, 읽는 순간 출력 여섯 개가 모두 레일 값이다(가장 먼 것도 레일에서 0.001 V 안). 방향 보기 읽기 8번이 모두 맞았으므로, 그린 그대로의 코어에서 데이터 0의 2비트 저장 오류는 고쳐지고({SEC, DED} = 11, 정상 읽기는 DED), 3비트 저장 오류는 정상 읽기가 틀린 값 + SEC인 것을 방향 보기는 검출(01)한다. ngspice는 조건 하나에 약 30분(2-core에서 두 조건을 나란히).
